# ADR-0003: 生成プロジェクトからテンプレート固有物とサンプルドメインを除去する

## ステータス

Accepted

## 関連 ADR

- 関連: ADR-0002（生成 CLI の配布方式。本 ADR は生成物の内容契約を定める）

## コンテキスト

ADR-0002 の生成方式は「テンプレートのファイル一式をコピーし、アプリ名を一括置換する」
だけであり、生成物には katagami 自身に固有の情報がそのまま残っていた。

- **テンプレート配布機構**: 生成 CLI（`scripts/new-project.sh` / flake の `apps.new`）と
  テンプレートについての ADR、CI の `template-smoke` ジョブ。生成先では自分自身を
  再生成する経路にしかならず、CI 時間（30 分枠）だけを消費する
- **katagami の自己紹介・作成経緯**: README の「縦串一覧」「テンプレートとして使う」節、
  ADR-0001 の「katagami は…縦串テンプレートであり」という自己言及、元リポジトリの PR 番号。
  アプリ名が置換された結果、生成先では「<app名> は縦串テンプレート」という誤った記述になる
- **サンプルドメイン Note**: 縦串の貫通例であり README にも「置き換える前提」と書いてあるが、
  生成先では手作業で 11 ファイルと 4 箇所の配線を削る必要があった

ADR-0002 は「不要なら削除してよい」と書いていたが、削除の判断と手順を利用者側に委ねると、
生成のたびに同じ手作業が発生し、消し漏れがそのままプロダクトに残る。

## 決定内容

生成時に上記 3 系統を機械的に除去する。除去ロジックの正本は
`scripts/strip-template-meta.sh` で、`scripts/new-project.sh` から
**アプリ名置換より前**に呼ぶ（除去側のアンカーをテンプレート原文のまま書けるため）。

- **サンプルドメインの除去は無条件**。フラグ（`--with-sample` 等）は設けない。
  残す選択肢を用意すると、生成物が 2 種類になりスモークで検証すべき組み合わせも倍になる。
  縦串の実装例が見たい場合はテンプレートリポジトリ自体を読めばよい
- **全操作はアンカーが見つからなければ即 fail する**。テンプレート側の構造変更で
  除去が空振りした場合に、生成物が黙って劣化するのではなく生成時点で落ちる
- 生成型（`web/src/api/generated.ts`）は Note 由来のエントリをテキスト除去する。
  正しさは CI の `template-smoke` が生成物で `make codegen-types` を実行し、
  実際の再生成結果と一致することで担保する（除去結果と真の生成結果の一致を機械検証）
- README は生成先向けの最小構成へ差し替える。テンプレートのカタログ（縦串一覧・
  生成手順・サンプルドメイン解説）は katagami 側の README にのみ置く

## 代替案

- **生成後に利用者が手で消す（ADR-0002 の現状）**: 消し漏れが常態化する。不採用
- **サンプルドメインをフラグで任意にする**: 生成物のバリエーションが増え、
  template-smoke で検証すべき組み合わせが倍になる。利用実態としても
  「サンプルを残したまま本番開発を始める」経路に価値がない。不採用
- **サンプルドメインを別ブランチ / 別ディレクトリに隔離する**: テンプレート本体が
  「縦串が実際に通っていること」を CI で示せなくなり、テンプレートの中核性質
  （常に `make ci` green）を弱める。不採用
- **生成型を除去せず、生成先の初回 `make codegen-types` に委ねる**: 生成直後の
  リポジトリに存在しないエンドポイントの型が残る。除去漏れとして目に触れる。不採用

## トレードオフ・既知のリスク

- 除去はアンカー（正規表現）ベースであり、テンプレート側のリファクタで陳腐化し得る。
  fail-fast と template-smoke の二重検証で「気づけないまま壊れる」ことは防ぐが、
  テンプレート改修時に除去スクリプトの追従が必要になるコストは残る
- `generated.ts` のテキスト除去は openapi-typescript の出力整形（インデント幅・
  doc コメントの位置）に依存する。生成器のメジャー更新時は template-smoke が落ちて表面化する
- 非同期タスク基盤の `TaskAccepted` は、サンプル除去後はどのエンドポイントからも
  参照されないため OpenAPI に現れない。Pydantic 側には残す（次のタスク API の契約として使う）

## 将来の移行条件

- 除去対象が増えてアンカーの維持が破綻した場合、テンプレート側にマーカーコメント
  （`# <template-only>` 等）を導入する方式へ切り替えることを別 ADR で判断する
- 複数テンプレート対応（ADR-0002 の `--template`）を実装する場合、除去ルールを
  テンプレートごとに持つ必要が出るため、配置を合わせて再設計する
